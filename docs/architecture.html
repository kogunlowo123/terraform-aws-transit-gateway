// terraform-aws-transit-gateway

Enterprise-grade AWS Transit Gateway with VPC attachments, custom route tables, RAM sharing, and inter-region peering support.

Terraform ≥ 1.5.0 AWS ≥ 5.20.0 MIT License

Executive Summary

This module provisions an AWS Transit Gateway with full-featured networking capabilities. It creates a Transit Gateway with configurable ASN, DNS support, VPN ECMP, and multicast. VPC attachments support per-attachment configuration including appliance mode for stateful firewalls. Custom route tables enable network segmentation with associations, propagations, static routes, and blackhole routes. Cross-account sharing is implemented via AWS RAM, and sub-modules provide spoke attachment and inter-region peering patterns. Input validation ensures CIDR correctness and ASN range compliance.

Traffic from VPC A enters the Transit Gateway via its attachment, is evaluated against the associated route table, and forwarded to the target VPC attachment. Blackhole routes drop traffic to restricted CIDRs. Route propagations enable dynamic route learning from attached VPCs.

Security Controls

Network Segmentation

Custom route tables isolate production from development traffic. Disable default route table association for explicit control.

Blackhole Routes

Drop traffic to unused or restricted CIDR ranges by adding blackhole routes

Appliance Mode

Enable for stateful firewall VPCs to ensure symmetric routing for IDS/IPS

RAM Governance

Share via organization-level ARNs with SCPs. Auto-accept only with strong governance.

DNS Isolation

DNS support enables cross-VPC resolution but may expose internal names -- control per attachment

Least Privilege

Route table associations implement least-privilege network access between VPCs

Production Readiness Checklist

  • Disable default route table association and propagation for explicit control
  • Create custom route tables for each environment (prod, dev, shared)
  • Add blackhole routes for unused CIDR ranges
  • Enable appliance mode for stateful network appliance VPCs
  • Use organization-level RAM sharing instead of per-account
  • Disable enable_auto_accept_shared_attachments unless SCPs are in place
  • Deploy VPC attachments in 2+ AZ subnets for HA
  • Enable VPC Flow Logs on all attached VPCs and TGW
  • Monitor data processing costs ($0.02/GB)
  • Tag all resources with Environment, CostCenter, and Owner

Deployment

module "transit_gateway" {
  source = "kogunlowo123/transit-gateway/aws"

  name = "my-tgw"

  vpc_attachments = {
    vpc_a = {
      vpc_id     = "vpc-aaa"
      subnet_ids = ["subnet-aaa1", "subnet-aaa2"]
    }
    vpc_b = {
      vpc_id     = "vpc-bbb"
      subnet_ids = ["subnet-bbb1", "subnet-bbb2"]
    }
  }

  tags = { Environment = "production" }
}
